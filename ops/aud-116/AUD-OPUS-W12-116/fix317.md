**What goes wrong:** a stale on-device import completion acts on the replacement sheet.
- `ConnectionsScreen` keeps one `ConnectProviderSheet` mounted and only changes `visible`/`provider` (`ConnectionsScreen.tsx:416-421`).
- The import continuation is checked against `mountedRef` only, never against the attempt epoch or fence:
  - `ConnectProviderSheet.tsx:250-289` (`handleImportOutcome`): emits the tutorial signal, calls `onConnected`/`onClose`, and sets `setResumeTarget`.
  - `:291-309` (`runImport` catch): calls `connectFailureMessage` (which reports to Sentry) and `showMessage`.
  - `:400-420` (`handleResume`): same gap.
  - `:459-461`: the old attempt's `finally` owns `requestingOnDevice`.
- An import can still finish after the sheet closes. `onDeviceSync.ts:161-168` returns the final pass with no fence check, and a final ingest POST that fails after close surfaces as `OnDeviceStepError('import')`.

**Reproduction:** the probe used the real sheet, plus the real `connectOnDeviceProvider`, `onDeviceSync`, fence and storage. It started Health Connect, held the import, dismissed the sheet and opened Oura. All 3 cases fail:
1. **Late success:** emits `wearable_connected`, calls `onConnected` and closes the Oura sheet.
2. **Late failure:** the Oura sheet shows the Health Connect history error with a reference, and a Sentry report goes out for the abandoned attempt.
3. **Stuck button:** the Oura sheet's Continue stays disabled and busy until the old import ends.

This is the same class as B-317-10, on the on-device path instead of the cloud path.

**Minimal fix:**
- Pass the attempt (epoch plus fence) into `runImport`, `handleImportOutcome` and `handleResume`.
- After `run()` settles, return silently unless `mountedRef.current && epochRef.current === epoch && attemptRef.current === fence`. Compute the failure message, and so the Sentry report, only for the current attempt.
- Make the busy state per attempt: reset `requestingOnDevice`/`importing` on `[visible, provider]`, and let `finally` clear them only while the attempt is current.
- Tests: the three cases above for close and reopen, plus unmount, sign-out and resume variants, and an unchanged-attempt positive control.

- C-317-c: the open-settings message after an await has only a mount check.
- C-317-d: a test name overclaims (`attemptFence.test.tsx:291`).
