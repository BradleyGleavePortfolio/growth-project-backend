### B: must fix before merge
- **B-641-5 (OR-112-16): package create ignores the Idempotency-Key, so a client retry creates a duplicate package.**
  - `PackagesController.create` (`src/packages/packages.controller.ts:96-112`) reads no `Idempotency-Key`.
  - `PackagesService.create` (`src/packages/packages.service.ts:146-169`) is a plain `coachPackage.create`. No global interceptor handles the header either: `APP_INTERCEPTOR` is only `RlsContextInterceptor` plus logging.
  - The paired mobile #329 setup wizard sends a stable key on purpose (`src/components/coach/setup/FirstPackageForm.tsx:198`, `coachPackagesApi.create(input, idemKey.current)`), and the server drops it.
  - A timeout or lost response on "Create package" followed by a retry gives the coach two draft packages with the same name and price, on their very first setup step.
  - Package create is outside this PR's diff, but the operator ruled that it must be idempotent end to end, and #641 is the backend half of the S-COACH money/setup pair.
  - **Minimal fix (this PR or a small companion T4 PR merged first):**
    - Read the header with `@Headers('idempotency-key')`. Make it optional for now, because mobile `CoachPackageEditScreen.tsx:189` does not send one yet; make it required once it does.
    - Wrap create in the same request-level claim that `PackagePushService.claimAndRun` uses (`package-push.service.ts:477-520`, the `WorkoutBuilderIdempotencyKey` ledger): scope `packages:create`, key `(coachId, key)`, and a SHA-256 of the canonical body.
    - On a replay with the same body, return the stored package. On the same key with a different body, return 422 `IDEMPOTENCY_KEY_REUSED` with specific copy. While the first request is still running, return 409 `IDEMPOTENCY_IN_PROGRESS` with a retry hint.
    - **Spec:** two sequential POSTs with one key produce one `CoachPackage` row and the same id; two concurrent POSTs produce one row; the same key with a changed body returns 422.
    - **Mobile follow-up:** `CoachPackageEditScreen` should send a key per intent too.
