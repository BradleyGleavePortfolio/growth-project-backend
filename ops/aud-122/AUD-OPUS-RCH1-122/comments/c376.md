### B-376-1: after today's chat is deleted from the new history button, the Roman chat still shows it, and every send fails

**Normal-user story:** a client chatting with Roman taps the new history icon in the chat header, deletes today's conversation (or uses Delete all), and taps Back. The deleted messages are still on screen, and every message they send fails with "That request did not complete. Send it once more, and I will try again." "Send again" fails the same way until they leave Roman and reopen it.

**Where**
1. This PR adds the header button: `RomanChatScreen.tsx:267` and `RomanConversationsButton.tsx:22`, which calls `navigate('RomanConversations')`. That pushes onto the same stack (More / coach Settings), so RomanChat stays mounted underneath.
2. `useRomanChat.ts:145-147` opens the session only on mount. Nothing reloads it on focus or after a delete:
   - `romanChatsEvents.emitGone` is emitted only by the transcript (`RomanConversationScreen.tsx:112`), and RomanChat does not listen to it.
   - `useRomanChats` `deleteOne` and `deleteAll` emit nothing.
3. The next send uses the erased id (`useRomanChat.ts:194`).
4. The backend send loads the session with `getOwnedSession`, filtered on `deleted_at: null` (backend `roman.controller.ts:123`, `roman.service.ts:239`), so it returns 404.
5. `romanApi.ts:483` maps the 404 to 'unavailable', and the screen shows ROMAN_SEND_FAILED with "Send again". The retry sends to the same erased id.
