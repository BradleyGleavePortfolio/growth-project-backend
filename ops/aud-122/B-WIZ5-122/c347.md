### B-347-4 (Sol, 6005829500; = Opus C-347-6): "Make live" no longer publishes stale terms
**Normal-user story:** a coach changes a draft from $99 to $199 and taps "Make Coaching live". Before this fix, the old $99 offer went live.

I picked the smaller safe option: block with plain copy, instead of save-then-publish.
- `src/screens/coach/payments/CoachPackageEditScreen.tsx`: the screen keeps a snapshot of the editable terms (name, description, price text, billing interval, features).
  - When the snapshot is set: when the package loads from `initialPackage`, and again after a successful **Save changes**.
  - `unsaved` is true when the form differs from that snapshot.
- While `unsaved` is true:
  - `handlePublish` sends no request. It shows the alert "Save your changes first" / "Save your changes before making this live."
  - The button is dimmed, and the plain line "Save your changes before making this live." shows under it (`testID package-edit-publish-unsaved`).
- After **Save changes** succeeds, the line goes away and the next tap publishes the stored row, which now holds the saved terms.
- If a save fails (for example, pricing is locked), the form stays unsaved and publishing stays blocked.
- An untouched draft still goes live in one tap.
- The button is not given `disabled`, so a tap is never silent.
