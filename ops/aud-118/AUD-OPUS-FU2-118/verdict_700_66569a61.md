## B-700-2: email addresses still reach log lines through text built from the address
The new README rule says: "Text the service does not write itself (a provider's error body, an exception message) goes through `redactEmailAddresses` first, because providers echo addresses back". The guard says every log call is clean. Two paths prove both claims false at this head, and both are on flows this PR edits.
- **(a) Supabase Auth errors.**
  - `src/auth/auth.service.ts:1474` logs `resetPasswordForEmail failed: ${error.message}`. This is the public forgot-password endpoint, and the caller supplies the address.
  - The same pattern is at `:879` (`generateLink` for `user.email`).
  - Supabase Auth returns `Email address "<address>" is invalid` (`email_address_invalid`; https://github.com/supabase/auth/issues/2252). `resetPasswordForEmail` returns it for blocked or MX-less domains (https://www.guardlayer.io/blog/supabase-email-address-invalid-password-reset).
- **(b) The finance federation path.**
  - `src/admin/federation/finance-admin.client.ts:166-167` logs `path=${path}` on every degraded outcome. The comment says "no PII; URL path only".
  - The paths at `:65`, `:73` and `:93` embed `encodeURIComponent(email)`.
  - This is the same practice-type call whose caller line (`practice-type.service.ts:107`) this PR moved off the coach email. `redactEmailAddresses` would not catch `%40` either.
  - The Sol lens reported this first (its C-700-1); I verified it with my own probe. I grade it B here because it is the flow this PR fixed and the guard claims every log call.
- **Probe:** run https://github.com/BradleyGleavePortfolio/growth-project-backend/actions/runs/37219384148 (branch `audit/AUD-OPUS-FU2-118/700-all`; head `b5df58cb` = this head + 3 probe specs + lane files). 4 failed and 10 passed; `no-pii-in-logs.spec.ts` PASSES in the same run.
  - `aud-opus-fu2-118-reset-email-probe.spec.ts` received: `resetPasswordForEmail failed: Email address "pat.client+tgp@example.com" is invalid`.
  - `aud-opus-fu2-118-finance-path-probe.spec.ts` received: `Finance federation degraded path=/api/admin/federation/coaches/by-email/pat.client%2Btgp%40example.com/practice reason=http_error`.
  - The coach-name probe of B-700-1 fails again in this run.
- **Fix rule:**
  1. Pass Supabase Auth error text from every auth call that carries an address and logs `error.message` through `redactEmailAddresses` (at least `:1474` and `:879`).
  2. Log a fixed route label in the finance client (e.g. `route=coaches/by-email/practice`), never the path.
  3. Add both cases to `no-pii-in-logs.spec.ts`, and make the guard's email rule also flag a `path`/`url` built from an address (or ban `path=${path}` in that client).
  4. Make the README rule's scope true.
