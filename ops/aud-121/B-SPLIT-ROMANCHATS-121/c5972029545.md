### A-331-7 — NOT CLOSED: a late old-account 401 refreshes A over a partly published B session

**Code:** `src/services/api.ts:404-407` starts a refresh using **current** `sessionGeneration()`, even when the failed unbound request's recorded `_sessionGeneration` is older. The request-generation check is only at `:432-436`, **after** refresh has written both tokens. `secureStorage.ts:98-104` / `sessionFence.ts:65-72` bump the generation and wait before ordinary writes, but do not hold the fence during that native write or across the sign-in's credential pair; `holdSessionFence(:80-81)` can therefore admit the late refresh in the gap. ([Actual transport](https://github.com/BradleyGleavePortfolio/growth-project-mobile/blob/c621770f262f3b04e734f3c34fde8342e51ca84c/src/services/api.ts#L404-L436), [write boundary](https://github.com/BradleyGleavePortfolio/growth-project-mobile/blob/c621770f262f3b04e734f3c34fde8342e51ca84c/src/services/secureStorage.ts#L98-L104), [fence](https://github.com/BradleyGleavePortfolio/growth-project-mobile/blob/c621770f262f3b04e734f3c34fde8342e51ca84c/src/services/sessionFence.ts#L65-L81))

**Executed interleaving, real interceptor/storage adapter, synthetic credentials only:**
1. An ordinary A request is sent; hold its eventual 401 at the adapter.
2. B starts the actual sign-in write sequence. B's access token lands; pause B's native refresh-token write. Storage is now B access / A refresh.
3. Release A's old 401. The handler captures the new generation, reads A's still-stored refresh token, and successfully publishes A's refreshed credentials under that generation.
4. The original request is correctly refused at the late replay check, but that does not undo the credential writes. Release B's pending write and finish B's sign-in: refresh belongs to B, **access is not B's**. Subsequent ordinary requests read that contaminated access credential.
The candidate's nine inherited race/positive controls all pass; the additional final stored-pair assertion alone fails. Thus this is a remaining account-boundary defect, not a harness import/typecheck failure. ([Independent one-job CI: 1 failed / 9 passed](https://github.com/BradleyGleavePortfolio/growth-project-mobile/actions/runs/37142864604/job/111260727647), [test-only audit branch](https://github.com/BradleyGleavePortfolio/growth-project-mobile/tree/audit/AUD-SOL-MOB/331-mid-signin-pair))

**Minimal fix rule:** reject an old-generation 401 **before initiating/joining any refresh or failure cleanup**, preserving the original 401 for an unbound request and account-change refusal for bound requests. Also make publication/removal of the whole session pair a genuine shared critical section that ordinary sign-in/sign-out writers hold for their complete awaited native writes; reads/refresh may not observe a mixed pair. A pre-write wait without owning the write interval is not that guarantee. Add this held-old-401 + held-new-refresh-write regression and require both final stored subjects and the next unbound request to remain B; keep ordinary refresh/sign-in/sign-out functionality and the existing positive controls.
