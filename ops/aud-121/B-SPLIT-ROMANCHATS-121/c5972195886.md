### A-331-7 — legacy migration writes old A's access token outside the new fence

`src/services/secureStorage.ts:50-56` reads an old `supabase_token` from AsyncStorage and calls `SecureStore.setItemAsync(key, legacy)` **directly**. It neither moves `sessionGeneration()` nor owns `runSessionWrite`'s native-write holder (`sessionFence.ts:88-106`). The new fence therefore protects explicit sign-in/sign-out writes but not this key migration on the first SecureStore read after an app upgrade. This was an older adapter path, but the shared adapter/fence is changed in this PR to claim **every** credential write and to prevent session resurrection; this is a remaining account-isolation defect in the changed boundary. ([Migration bypass](https://github.com/BradleyGleavePortfolio/growth-project-mobile/blob/5b58a1218acb1f5ba15cada8b8eaf8b78c75a058/src/services/secureStorage.ts#L50-L56), [new write boundary](https://github.com/BradleyGleavePortfolio/growth-project-mobile/blob/5b58a1218acb1f5ba15cada8b8eaf8b78c75a058/src/services/secureStorage.ts#L90-L112), [fence](https://github.com/BradleyGleavePortfolio/growth-project-mobile/blob/5b58a1218acb1f5ba15cada8b8eaf8b78c75a058/src/services/sessionFence.ts))

**Executed counterexamples** use the actual Axios interceptors, adapter and session fence with paused native SecureStore operations and synthetic A/B credentials. In both, the legacy A migration has started writing and is paused; (1) B's complete sign-in finishes, then the paused migration lands and leaves **A access / B refresh**, and (2) sign-out removes both keys, then the paused migration lands and **resurrects A's access token**. The two new assertions fail while ten inherited controls pass, including the original late old-401/mid-B-write interleaving. No local heavy work, live network or production credentials. ([One-job proof: 2 failed / 10 passed](https://github.com/BradleyGleavePortfolio/growth-project-mobile/actions/runs/37144136085/job/111264479284), [candidate test source](https://github.com/BradleyGleavePortfolio/growth-project-mobile/commit/5b58a1218acb1f5ba15cada8b8eaf8b78c75a058))

**Minimal fix rule:** make the migration of either session key participate in the same generation check **from before the legacy read** through the native copy and legacy removal. If sign-in/sign-out moved the generation during that read, refuse the stale copy; once a migration starts the native write, hold the shared fence through its completion so later sign-in/sign-out writes run after it. Do not hold a sign-out fence while attempting a migrating read that can wait on itself. Keep single-flight behavior. Add these two executed tests and a sign-out/sign-in during a paused *legacy read* to the candidate, require failing-before/passing-after CI and unchanged ordinary upgrade/migration controls. ([Legacy read/copy](https://github.com/BradleyGleavePortfolio/growth-project-mobile/blob/5b58a1218acb1f5ba15cada8b8eaf8b78c75a058/src/services/secureStorage.ts#L50-L72), [new fence](https://github.com/BradleyGleavePortfolio/growth-project-mobile/blob/5b58a1218acb1f5ba15cada8b8eaf8b78c75a058/src/services/sessionFence.ts))
