### B-331-7 (new, in the shared transport this PR changes): the overtaken-refresh fence is check-then-write with await gaps
- **What the PR claims (body):** "`performRefresh` never writes an overtaken refresh's tokens over a new session and never signs the new session out".
- **What the code does:** `api.ts:210` reads `supabase_refresh_token`, compares it, then `await`s two separate SecureStore writes (`:216-217`).
  - Neither the check nor the writes are tied to the auth epoch.
  - Neither is serialized with the sign-in/sign-out writers: `LoginScreen.tsx:265`, `CreateAccountScreen.tsx:696`, `appleAuth.ts:244`, `googleAuth.ts:186`, `authActions.signOut`.
- **Two executed probes**, using this PR's own real-axios transport harness with only the SecureStore double changed so a native read returns the value as of when it was issued: `ops/aud-opus-114b/331-probe.test.ts`, `CI=true npx jest --runInBand --forceExit --runTestsByPath src/services/__tests__/zzAud331Probe.test.ts -t "probe 331"`, 2/2 pass, so both defects are confirmed.
  1. **B signs in while the post-refresh check read is in flight.** A's refreshed access and refresh tokens overwrite B's. B's next *unbound* request (`GET /messages`) goes out with A's credential while the UI shows B. That is a cross-account session swap; bound Roman requests are still refused, but everything else is not.
  2. **Signed out while the access-token write is in flight.** Both of A's tokens are written back after `signOut` cleared storage and emitted `logout`. A's session comes back after sign-out on a shared device.
- **Scope:** the window is narrow, tens of ms around SecureStore I/O. Main has the same defect with a wider window, so it is pre-existing. This PR introduced the fence and states it as a guarantee in the shared client, so it should be correct.
- **Minimal fix:**
  - Capture `authEpoch()` when `performRefresh` starts.
  - Run "check the epoch and stored refresh token, then write both tokens" as one critical section on a small auth-storage mutex (promise chain) that the sign-in/sign-out token writers also take. Alternatively, bump the epoch synchronously *before* those writers touch storage and re-verify after the refresh writes, restoring or deleting if the epoch moved.
  - Add both probes as failing-before tests.
  - Same-account refresh must keep working (the existing positive control).
