## Live bug fixed (with the flag ON or OFF)
The thread routes return `sender_id`, not `sender_role`. Both screens read `sender_role`, so every bubble rendered on one side. The coach screen showed every message as the client's, and the client screen showed every message as the client's own. The side now comes from `sender_id` (`threadV2.resolveSenderRole`): on the client screen, `sender_id === me` is the client; on the coach screen, `sender_id === clientId` is the client and anything else is the coach side, which covers teammates too. A row with no `sender_id` keeps any `sender_role` it carries.

## What changes
| Area | Flag ON | Flag OFF |
|---|---|---|
| Send | `POST /messages` or `/coach/clients/:id/messages` with `client_message_id` in the body and the same `Idempotency-Key` header. Client: a network/5xx/429 failure leaves a "Not sent. Long press to send again" bubble that keeps its key, and Send again replays that key. Coach: the key is kept for the same text, so tapping Send again replays it. A 2xx with an unreadable shape counts as sent (refetch, no resend). Other refusals keep the typed text and show the server code's own copy. | unchanged |
| Reply | `reply_to_id`. The server quote (`reply_to`: text / voice / deleted / unavailable) is rendered, so quotes survive reloads and hide deleted or blocked targets. | Reply hidden (`MessageActionSheet canReply`). The legacy routes reject a reply reference with 400. |
| Read | `POST .../read { up_to_message_id }` with the newest incoming message in the page just fetched. A message that arrives after the fetch stays unread. | unchanged |
| Long-press (`threadV2.messageActionOptions`) | Reply, Copy, Edit (author, text, under 48 h), Pin / Unpin, Delete for everyone (author, under 48 h, asks first), Report (other person's message). Tombstones: Report only, for the other person. | legacy sheet |
| Edit | Sheet; `PATCH .../:id { body }`; "Edited" marker. | n/a |
| Pins | Pinned bar (`GET .../pins`). Tapping it jumps to each pin in turn, or says to tap Load older. `POST`/`DELETE .../:id/pin`. | n/a |
| Mute | Header bell: 1 h / 8 h / 1 d / 7 d / until turned back on / Unmute (`PUT .../mute`). The client's state comes from `GET /messages/inbox`. | n/a |
| Realtime | `thread-updated` refetches the thread and pins. On the coach screen it only does so for this client. | n/a |
| Fallback | A 503 `messaging.feature_disabled` on any v2 call switches the screen to legacy, and the typed text is kept. | n/a |
