### B-658-1 — a sub-coach's new code attaches clients to the sub-coach, not the head coach (team-mode tenancy)
- **Evidence:**
  - Team Mode (ADR-0001 §10 Q5) routes a code issued by a sub-coach under the head coach: `coach_id = head`, `invited_by_user_id = sub-coach`. See `invite-codes.service.ts:395-410` `resolveTeamAttribution`, used by the legacy `POST /coach/invite-codes`. Sub-coaches are `User.role = 'coach'` with a `TeamSubCoachAssignment`, so they pass `CoachGuard`.
  - The new `CoachCodeToolsService.create` writes `coach_id: actor.id` (`coach-code-tools.service.ts:265`) and never resolves attribution.
- **Impact:**
  - A client who joins with a sub-coach's A2 code gets `User.coach_id = sub-coach`. They land outside the head coach's roster, packages and money, against the team contract.
  - The head coach never sees, rotates or revokes that code. The leak-detection goal of this PR fails for team accounts.
  - Packages: `setBinding` then validates against the sub-coach's own packages.
- **Minimal fix:**
  - In `create`, resolve attribution the same way the legacy create does: reuse `resolveTeamAttribution`, made non-private or exposed through `InviteCodesService`. Write `coach_id = effective_coach_id` and `invited_by_user_id = sub-coach`.
  - Decide the scope of list/rotate/revoke/signups for a sub-coach. Recommended: the head coach's codes filtered to `invited_by_user_id = me`, with mutations allowed only on their own codes. Alternatively, refuse A2 for sub-coaches with a specific 403 for now.
  - Add tests: sub-coach create → row `coach_id = head`; a redemption attaches to the head coach; the head coach's list shows it.
