## B list

### B-PLAYREV-1 — Day-one health build declares an unused microphone permission

**Normal-user story:** An Android client installs the day-one health app, whose build declares microphone access for voice notes even though the voice-recording feature is off, exposing the release to Play's unused-permission rule. ([Audio build configuration](https://github.com/BradleyGleavePortfolio/growth-project-mobile/blob/a727eb495a0ce381a22c4ac40370c0c69f53a656/app.json), [voice-note feature default](https://github.com/BradleyGleavePortfolio/growth-project-mobile/blob/a727eb495a0ce381a22c4ac40370c0c69f53a656/src/config/featureFlags.ts), [Google health-app permission policy](https://support.google.com/googleplay/android-developer/answer/16679511?hl=en))

- **Exact location:** `app.json:143-148`: the always-registered `expo-audio` plugin sets both background options false but omits `recordAudioAndroid`; Expo SDK 56 defaults that option to true and adds `android.permission.RECORD_AUDIO`. ([App configuration](https://github.com/BradleyGleavePortfolio/growth-project-mobile/blob/a727eb495a0ce381a22c4ac40370c0c69f53a656/app.json), [Expo Audio configuration](https://docs.expo.dev/versions/v56.0.0/sdk/audio/))
- **Reachable feature state:** `src/config/featureFlags.ts:146-149` defaults voice notes off, and `src/navigation/CommunityNavigator.tsx:93-98` does not register the recording screen when off; neither store profile explicitly enables the voice-note flag. ([Feature flag](https://github.com/BradleyGleavePortfolio/growth-project-mobile/blob/a727eb495a0ce381a22c4ac40370c0c69f53a656/src/config/featureFlags.ts), [recording route gate](https://github.com/BradleyGleavePortfolio/growth-project-mobile/blob/a727eb495a0ce381a22c4ac40370c0c69f53a656/src/navigation/CommunityNavigator.tsx), [store profiles](https://github.com/BradleyGleavePortfolio/growth-project-mobile/blob/a727eb495a0ce381a22c4ac40370c0c69f53a656/eas.json))
- **Why B:** Google explicitly requires unused health-app permissions to be removed; this is a store/legal consequence, not an allegation that the app secretly records audio. ([Health Content and Services policy](https://support.google.com/googleplay/android-developer/answer/16679511?hl=en))
- **Evidence:** direct evaluation of the installed `expo-audio` config plugin using the repository's exact options produced `RECORD_AUDIO` and `MODIFY_AUDIO_SETTINGS`; the saved inspection is `ops/aud-123/S-PLAYREV-123/static-inspection.json`, reproducible with `node ops/aud-123/S-PLAYREV-123/static-inspection.js`. ([Configured options](https://github.com/BradleyGleavePortfolio/growth-project-mobile/blob/a727eb495a0ce381a22c4ac40370c0c69f53a656/app.json), [documented Android audio-permission default](https://docs.expo.dev/versions/v56.0.0/sdk/audio/))
- **Smallest fix:** explicitly set `recordAudioAndroid: false` in the existing audio plugin for the voice-off launch build; keep the dependency and background options unchanged.
- **Acceptance:** the builder should verify that the resolved store configuration/final manifest lacks `RECORD_AUDIO` with voice off; no recording, playback, Health Connect or notification feature needs to be removed.
