## API compatibility (read 14:4x-14:5x PDT)

- Ids and prices: [models overview](https://docs.anthropic.com/en/docs/about-claude/models/overview) lists `claude-sonnet-5-5` ($2 / $10), `claude-opus-5-5` ($4 / $20), `claude-haiku-4-5-20251001` ($1 / $5); Sonnet 5.5 thinking "Adaptive", default effort `high`; Opus 5.5 "Adaptive (always on)", default effort `medium`.
- Sampling params: "Claude Sonnet 4.6 and earlier models and Claude Haiku 4.5 accept temperature, top_p, and top_k. On Claude Sonnet 5.5, a non-default value returns a 400 error. Remove them." ([Sonnet 5.5 migration guide](https://platform.claude.com/docs/en/models/sonnet-5-5/migration-guide)); Opus 5.5: "Omit temperature, top_p, and top_k, or leave them at their defaults: any other value is rejected." ([Opus 5.5 migration guide](https://platform.claude.com/docs/en/models/opus-5-5/migration-guide)). Every Anthropic request in `src/` now sends none.
- Thinking defaults and low latency: "On Claude Sonnet 5.5, a request with no thinking field runs with adaptive thinking ... On Claude Sonnet 4.6 and earlier models ... that request ran without thinking." and "To turn off up-front thinking on Claude Sonnet 5.5, send thinking: {"type": "between_tools"} ... `disabled` returns a 400 invalid_request_error" and "`between_tools` ... is accepted at low, medium, and high effort" (Sonnet 5.5 migration guide). Roman therefore sends `between_tools` so the first streamed word is not delayed by thinking and `max_tokens` (1024) still covers only the reply, as on 4.6. Effort: "For chat and other latency-sensitive work, start with medium or low." ([Effort](https://platform.claude.com/docs/en/build-with-claude/effort)); Roman uses `medium` for the whole conversation ("With between_tools, effort can't change mid-conversation"). Coach AI uses `high`, the effort claude-sonnet-4-6 ran these calls at by default.
- Opus 5.5 brief: "Send no thinking field, or send thinking: {"type": "adaptive"} ... thinking: {"type": "disabled"} and manual thinking budgets ... are rejected" and "max_tokens remains a hard limit on total output, thinking plus response text" (Opus 5.5 migration guide). The brief sends no `thinking`, effort `low`, `max_tokens` 2048. Effort `low` rather than higher: the brief is prepared inside `GET /coach/brief/today` on a coach's first open of the day, and two attempts (call + repair) at the unchanged 15 s timeout must fit the app's 40 s request timeout (`COACH_BRIEF_REQUEST_TIMEOUT_MS`); "At lower levels, Claude can skip thinking entirely for simpler problems" (Effort page). Text is selected by block type (`find(b => b.type === 'text')`), so leading `thinking` blocks are ignored.
- Prefill: rejected on 5.5 "as Claude Sonnet 4.6 and Claude Sonnet 5 do"; no call site prefills (Roman history ends on the user turn; the adapter sends one user message).
- Forced tool use (`tool_choice` any/tool) is rejected on 5.5; no call site sets `tool_choice` or tools.
- Stop reasons: a decline is `stop_reason: "refusal"`; every path already treats empty text as a failure (Roman failure copy, brief fallback narrative, adapter error), unchanged.
- SDK `@anthropic-ai/sdk` 0.104.1: `Model` is `... | (string & {})`, so the new ids type-check; `OutputConfig.effort` has `low | medium | high | xhigh | max`; `ThinkingConfigParam` is `enabled | disabled | adaptive` only, so `between_tools` is not in its types. The SDK sends the body as given, so `AiEgressService.anthropicMessagesCreate/Stream` accept `ThinkingConfigParam | { type: 'between_tools' }` and hand the SDK its own param type at the one call each (a plain `as Anthropic.MessageCreateParamsNonStreaming` / `as Anthropic.MessageStreamParams` downcast from the wider union; no R75 token).
