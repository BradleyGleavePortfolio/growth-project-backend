## Fixes

- **B1 — coach cannot set a client's targets anywhere.** A coach opens a client, taps Macros to set calories and protein, and reads "No target set. Use the prescriber to issue the first target." — there is no prescriber in the app (useCreateMacroTarget had no caller), so no coach can prescribe a client's daily calories or macros. Now: a "Set daily targets" form (calories, protein, carbs, fat, optional note), prefilled from the current target, validated with the server's own limits (800-7000 kcal, protein 0-500 g, carbs 0-900 g, fat 0-400 g) with field-specific copy, the implied kcal of the grams, specific save-failure copy (404 roster, 400, 429, network), and React Query invalidation so the Summary and Food log review target lines refresh. A failed load now shows Retry instead of claiming there is no target, and the no-target copy says what the client sees meanwhile.
- **U1 — Home targets disagree with the Food Log.** A client whose coach set 2,400 kcal sees "2400 goal" on the Food Log but a different number (or none, for consultation-onboarded clients) on Home, because Home read the phone's onboarding cache (`profile.calorie_target`, a value the server ignores) instead of the server's targets. Home now uses the same GET /me/macros/current hook as the Food Log; cached profile numbers are only a first-paint fallback.
- **U2 — Home shows another day's food as today.** A client looks back at yesterday on the Food Log, taps Home, and sees yesterday's meals count and calories under today's date (the day store is shared). Home now loads today on mount, on pull to refresh, and on focus when the store holds a different day.
- **U3 — water silently undone.** With a weak connection a client taps +8 oz, the number goes up, then quietly goes back down. Now the screen says "8 oz of water was not saved. Check the connection, then add it again."
- **U4 — water copy.** "1 glasses today" (and "today" on a past day) now reads "1 glass (8 oz)" / "3 glasses (8 oz each)".
- **U5 — Water Goal setting ignored.** A client sets Water Goal to 64 oz in Settings, but the Food Log water card keeps saying "/ 128 oz" (a fixed default that does not even match the Settings default of 100). WaterTracker now uses the Settings goal; useSettings instances share saves, so the change shows without a restart.
