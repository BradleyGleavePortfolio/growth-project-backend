### B-345-1 — a cadence change after the package was made never reaches the server
- Where: `src/lib/coachSetup/packageCreateIntent.ts:331-334` (step "details changed after the package was made -> update it") calls `deps.update(packageId, input)` with the full create input; `src/api/packagesApi.ts:439-447` `toBackendUpdate` sends only `name`, `description`, `amount_cents`, `currency`, `is_active` and drops `billingInterval` / `intervalCount`. The comment at `packagesApi.ts:435-436` is stale: backend main `UpdatePackageDto` accepts `billing_type`, `billing_interval`, `billing_interval_count` (`src/packages/packages.dto.ts:115-128`).
- Counterexample (probe above): package made as $49 monthly, coach then picks One time: PATCH body is `{name, description, amount_cents: 4900, currency}` with no `billing_type`. Money consequence through the form (see #346 probe): the package is published as a monthly subscription while the app reports a one-time package. Paid to Free: PATCH `{amount_cents: 0}` on a recurring package, which backend main rejects with `PACKAGE_FREE_MUST_BE_ONE_TIME` (`packages.service.ts:870-874`) on every retry, so the coach cannot finish. One time to monthly: the recurring cadence is lost. The existing durability test cannot see this because its `update` mock discards the body (`packageCreateDurability.test.tsx:47,52` in #346).
- Fix rule: `toBackendUpdate` maps `billingInterval` / `intervalCount` exactly as the create body does (one_time -> `billing_type: one_time`; monthly -> `recurring` + `month` + count), and the stale TODO goes. Tests assert the exact PATCH body for monthly->one-time, one-time->monthly and paid->free. Closure: the probe spec passes at the new head, with a failing-before CI lane run. Side effect: this also fixes the package editor on main, where interval edits are silently dropped the same way (`CoachPackageEditScreen.tsx:183-184`, outside this diff).

### B-329-5 (Sol, retained; helper part) — the helper admits a create after the owner or mount has changed
- Where: `packageCreateIntent.ts:322-329`: `await saveIntent(...)` -> `onIntent(fresh)` -> `send(fresh)` with no liveness check. - Fix rule: `createPackageOnce` takes an `isLive()` predicate (account and mount) and checks it after every await before `onIntent`, `send`, `update` and `remember`.
