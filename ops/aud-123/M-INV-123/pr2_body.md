Independent of part 1 (m#385, client refusal copy); both are based on main. Sits dark until the operator sets FEATURE_COACH_CODE_TOOLS=true after a lens pair and a device pass.

Story: a coach whose code leaked sees "Many more signups today than usual" on that code, turns it off, creates a new one and shares its QR. Clients who already joined stay connected; a client who types the old code sees the part 1 sentence ("This code was turned off by your coach").

What this does
- `src/screens/coach/CoachCodesEntry.tsx` is the component for the existing `InviteCodes` route (Clients, Home, Messages and Settings all reach it). It calls `GET /coach/codes` once: success shows the new Codes screen with that data; a 404 (`coach_code_tools_disabled`, or a bare 404 from an older backend) shows the legacy `InviteCodesScreen` unchanged; any other failure shows what happened and Try again (never a silent fallback).
- `src/api/coachCodesApi.ts`: list, signups(8 days), create (`Idempotency-Key` header; the screen mints one key per create attempt and reuses it on every retry of the same inputs, so a timeout and a retry return the first code), rotate (`grace_hours`; `expected_code` = the code on screen for `coach-link`), revoke. One sentence per server refusal (`code_rotation_conflict`, `coach_link_head_coach_only`, `code_package_head_coach_only`, `coach_link_not_revocable`, `code_already_revoked`, `code_not_found`, `idempotency_key_invalid`, `expiry_in_past`, `label_too_long`), never the raw server string.
- `src/screens/coach/CoachCodesScreen.tsx`: coach link first, then codes with status (Active / Retiring / Off / Expired / Used up); today's signups, 7-day and total counts, "n of m used"; the `unusual_today` warning; Share (text + link), QR sheet (Share QR image via react-native-view-shot + expo-sharing, both existing deps; Share link), Rotate with a grace sheet (off now / keep 24 hours / keep 7 days; a modal, not an Alert, because Android shows at most three Alert buttons), Turn off with a confirmation (not offered on the coach link, which can only be rotated). A retiring code can only be turned off early. Sub-coaches get no coach link row (server sends none). Create: optional name, signup limit, days until it stops working. The legacy screen's two links move with it: "Bulk invite from a list" (CoachBulkInvite) and "Who joined" on codes with signups (InviteCodeRedeemers), so flipping the flag removes nothing coaches use today.
- QR: `src/lib/qrMatrix.ts` + `src/components/coach/CodeQr.tsx`, black on white with a 4-module quiet zone, encoding the server's `qr_payload` (`https://app.trygrowthproject.com/join/<code>`).

New dependency (justification): `toqr` 0.1.1, pinned. It is already in package-lock.json (the Expo CLI prints its dev-server QR with it), MIT, pure TypeScript, no native code, so it works in Expo managed builds and nothing new is downloaded; the lockfile change is one line in the root dependency list (`npm ls --package-lock-only toqr` resolves it deduped). `react-native-qrcode-svg` was the brief's preference; it would add `qrcode` plus the deprecated `text-encoding` package and a fresh install for the same output. Rendering stays on `react-native-svg` (a direct dependency). The encoder output was checked by decoding it with OpenCV's QRCodeDetector: the 29x29 matrix for `https://app.trygrowthproject.com/join/GP-7XQ9KM` decodes back to the same string.
