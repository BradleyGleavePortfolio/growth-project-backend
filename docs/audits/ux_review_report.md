# UX Review Report — Premium / Rewarding / Cognitively Simple

_Generated: 2026-05-26. Read-only audit of 203 source surfaces: 176 mobile TSX surfaces and 27 platform-site page surfaces._

## Executive summary

Overall verdict: the product has a real premium foundation, but only selected client/onboarding surfaces currently feel decacorn-grade end to end; the average product experience is closer to solid mid-market utility than Apple/Stripe/Linear polish. The gap is not primarily color choice—the token system already defines bone/cream/ink/forest restraint, Cormorant display type, subtle radius, and velvet motion—but inconsistent application, dense operational screens, and under-designed confirmation moments prevent the app from satisfying the visceral/behavioral/reflective model described in the mobile doctrine ([Mobile Doc §1.2](../Mobile-App-Design-Intelligence-Exhaustive-Agent-Training.md#L52-L129), [tokens](../repos/growth-project-mobile/src/theme/tokens.ts#L30-L62), [tokens typography/motion](../repos/growth-project-mobile/src/theme/tokens.ts#L131-L286)).

Biggest strengths: client Home, Day 1 Win, day-one onboarding, LeanQ onboarding, Share Card, Trust Center, platform Apply, Pricing, and the newer coach command-center surfaces show the right mental model: one idea per screen, restrained visual language, visible progress, and clear next action. These surfaces align with the documents’ instructions to make first use frictionless, show progress before demanding commitment, and preserve simplicity by moving complexity behind progressive disclosure ([Mobile Doc §2.1 onboarding](../Mobile-App-Design-Intelligence-Exhaustive-Agent-Training.md#L235-L323), [Mobile Doc §4.5](../Mobile-App-Design-Intelligence-Exhaustive-Agent-Training.md#L1237-L1300), [Website Doc §7.3 form protocol](../Website-Landing-Page-Design-Intelligence-The-Exhaustive-Agent-Training-Document.md#L971-L1009)).

Biggest weaknesses versus the decacorn bar: the rewarding layer is thin across most surfaces, and the coach/admin/payment/settings areas expose too many controls at once. Too many success states are functional rather than emotional, many mobile screens lack visible haptics/animated closure, and several high-stakes flows look like control panels instead of calm confidence-building experiences; that conflicts with the docs’ standard that every completion event deserves a micro-interaction and every screen should have one primary path ([Mobile Doc §5.1](../Mobile-App-Design-Intelligence-Exhaustive-Agent-Training.md#L1456-L1498), [Mobile Doc §3.5](../Mobile-App-Design-Intelligence-Exhaustive-Agent-Training.md#L874-L918), [Mobile Doc §4.4](../Mobile-App-Design-Intelligence-Exhaustive-Agent-Training.md#L1180-L1236), [Website Doc §4.1](../Website-Landing-Page-Design-Intelligence-The-Exhaustive-Agent-Training-Document.md#L423-L464)).

## Methodology and scoring caveats

Scores use the provided 1–5 rubric for Premium, Rewarding, and Cognitively Simple, where 5 means Apple/Stripe/Linear-grade and 1 means generic, cheap, or overwhelming ([rubric](ux_review_rubric.md#L12-L42)).

I inventoried every `**/*.tsx` mobile source surface and every platform `app/**/page.tsx`; test files and component modules are included in the heatmap because they are part of the requested 203-surface count, but the worst/strongest lists exclude test harnesses so the product recommendations stay focused on user-facing UX.

Representative duplicate clusters were scored by shared pattern rather than by line-by-line review, which is appropriate for repeated list/form/admin surfaces and consistent with the task instruction to group similar screens efficiently.

## Cross-cutting findings

- **Premium baseline exists, but legacy drift is visible.** Tokens define a clear luxury language—bone/cream/ink, forest accent, Cormorant/Inter, 0–4 radius, subtle shadows, and velvet motion—yet older payment/admin/settings screens still read like generic app utility because implementation mixes old colors, hardcoded values, larger radii, and dense cards ([tokens palette](../repos/growth-project-mobile/src/theme/tokens.ts#L30-L62), [tokens radius/shadows](../repos/growth-project-mobile/src/theme/tokens.ts#L230-L268)).
- **The client/new-user side is materially better than the coach/operator side.** Home, day-one, LeanQ, and Apply honor “motion before commitment,” one-question sequencing, and clear closure, while coach AI drafts, package admin, settings and invite screens expose the work instead of absorbing it ([Mobile Doc onboarding](../Mobile-App-Design-Intelligence-Exhaustive-Agent-Training.md#L1507-L1545), [Mobile Doc invisible complexity](../Mobile-App-Design-Intelligence-Exhaustive-Agent-Training.md#L1024-L1063)).
- **Reward is the weakest dimension.** Only workout/progress/habits/share/onboarding surfaces show recurring progress or payoff; most actions end in static state, Alert-like utility, navigation, or silent success despite the doctrine that every meaningful completion needs animation, haptic, color shift, or character-scale feedback ([Mobile Doc confirmation rule](../Mobile-App-Design-Intelligence-Exhaustive-Agent-Training.md#L1487-L1498), [Website microinteractions](../Website-Landing-Page-Design-Intelligence-The-Exhaustive-Agent-Training-Document.md#L873-L932)).
- **Progressive disclosure is inconsistent.** Apply and onboarding are strong because they sequence decisions; notification preferences, AI draft editors, package creation, and settings violate the same principle by presenting matrices or long forms up front ([Mobile Doc progressive disclosure](../Mobile-App-Design-Intelligence-Exhaustive-Agent-Training.md#L1237-L1300), [Website form protocol](../Website-Landing-Page-Design-Intelligence-The-Exhaustive-Agent-Training-Document.md#L980-L1009)).
- **Data surfaces need tactile treatment.** Progress, earnings, metrics, risk, and analytics surfaces largely present data as cards/lists; Revolut-style tactile charts, ring closure, counter animation, and direct manipulation would make progress feel owned rather than reported ([Mobile Doc Revolut data](../Mobile-App-Design-Intelligence-Exhaustive-Agent-Training.md#L543-L568), [Mobile Doc rings](../Mobile-App-Design-Intelligence-Exhaustive-Agent-Training.md#L920-L970)).
- **Platform marketing is premium but over-explains above the fold.** The homepage architecture is strong, but the hero pattern appears to exceed the web doc’s five-element maximum through multiple text blocks and multiple CTAs, which weakens 50ms clarity ([Website 50ms](../Website-Landing-Page-Design-Intelligence-The-Exhaustive-Agent-Training-Document.md#L18-L52), [Website hero formula](../Website-Landing-Page-Design-Intelligence-The-Exhaustive-Agent-Training-Document.md#L444-L464)).
- **Admin/owner pages optimize clarity, not brand feeling.** That is acceptable for internal utility, but the same visual vocabulary should not leak into paid/coach-facing flows where high-trust premium perception directly matters ([Website trust threshold](../Website-Landing-Page-Design-Intelligence-The-Exhaustive-Agent-Training-Document.md#L741-L783), [Mobile polish-as-trust](../Mobile-App-Design-Intelligence-Exhaustive-Agent-Training.md#L391-L407)).
- **Test and component files should be classified separately in future audits.** The requested glob count includes test harnesses and low-level components, which are useful for engineering coverage but should not be weighted equally with navigable customer screens in future UX dashboards.
